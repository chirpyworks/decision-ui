# Community Fork Showcase

This page is for public Decision UI forks that make a meaningful adaptation while preserving the project's evidence and truthfulness boundaries.

A listing is not an endorsement, benchmark result, security review or quality certification.

## What qualifies

A useful showcase fork should do at least one of these:

- define a real team house style,
- add a reusable domain reference,
- add meaningful local evaluation cases,
- adapt the method to a different design system or implementation stack,
- document a counterexample or boundary that improves the community's understanding.

A fork that only changes the repository name, colors or README branding is not enough.

## Submission requirements

Submit through the **Fork showcase** issue template and include:

- public fork URL,
- what was changed,
- why a fork was necessary instead of a normal install,
- which upstream files remain unchanged,
- any new evidence/evals,
- limitations,
- license compatibility.

Do not submit forks containing private data, credentials, proprietary customer material or unsupported performance claims.
